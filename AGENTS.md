# Agent guide

This file is the entry point for agents working on Dama Pinoy. Read [README.md](README.md) for setup, gameplay, and dependencies, and [CHANGELOG.md](CHANGELOG.md) for release history. There is no separate formal product specification in this repository.

## Project map and conventions

- `index.html`: seven accessible screens and settings/controls. Use semantic markup, labeled inputs, keyboard-accessible buttons, and the existing DOM IDs.
- `style.css`: wood-first board-game design with Night and Light themes, consistent spacing/surfaces, visible focus, reduced-motion support, and responsive layouts. Keep the title usable at short desktop heights and prevent horizontal overflow on mobile.
- `script.js`: self-contained Dama rules, AI, series, replay, and browser storage. Keep the current test hook under `__DAMA_TEST__` and reuse it for behavioral checks. Red moves first in every game as this app's convention; Player 1/the human chooses a Game 1 color and players swap colors each series game. Player 1's pieces appear at the bottom: visually reverse board squares and coordinate labels when Player 1 is Blue, without changing logical row/column, notation, or rules. Keyboard board navigation follows visual directions; new replays retain the game's view and replay version 1 uses the original Red-bottom view. Player IDs (`P1`, `P2`) own names and scores; board colors (`R`, `B`) own pieces and moves. Existing `R`/`B` names and scores migrate to `P1`/`P2`; saved replay version 1 remains readable. The AI must play whichever color belongs to `P2`. `MATCH_GAME_LIMITS` defines valid formats and their game limits; the series ends on a majority of wins or at that limit. At the limit, the higher score wins or a tie draws the match. Draws consume a game but award no series point. An ordinary piece that reaches the far row during a capture chain keeps jumping as an ordinary piece and promotes only when that turn ends there.
- `manifest.json`, `service-worker.js`, `icons/`: local PWA assets. Increment the versioned service-worker cache name when changing cached app files, so installed clients receive updates. Register only on localhost or HTTPS.
- Statistics are stored under `damaPinoyStatsV1` and are separate from the all-time win counters. Record only completed games and finalized matches; restarts, abandoned games, and replay viewing must not record. Local two-player results use Player 1's perspective; vs Computer results use the human player's perspective. AI mode keys are `vsEasy`, `vsMedium`, and `vsHard`; drawn series count as played but not won or lost. Reset Statistics must preserve names, preferences, the saved replay, the active game, and the all-time win counters.
- Replay downloads use a separate JSON file format (`format: "dama-pinoy-replay"`, `version: 1`) with `P1`/`P2` ownership, ordered captures, and an explicit Red- or Blue-bottom view. The internal stored replay versions 1 and 2 remain readable. Export the open replay from the viewer or the saved replay from Game Over. Import validates metadata and board sequence before opening the read-only viewer; it remains in memory and must not replace Last Replay or change the game, statistics, scores, names, or preferences. Use visible non-blocking status text; file transfer must work offline and over `file://`.
- Online Single Game and rematches live in `online.js`/`online-rules.js`, separate from local game state and statistics. `online-rules.js` is also imported by the Supabase Edge Function; keep it in parity with the local Dama rules. A verified anonymous Supabase Auth user ID owns each room seat; the guest ID in localStorage is informational, never authorization. Private Broadcast/Presence messages are hints only: fetch and validate the database snapshot before rendering. Edge Function checks full moves; service-role-only SQL RPCs commit them atomically. No online result changes local scores, statistics, names, or Last Replay. Red opens every game. Online scripts are local/cached, but the Supabase CDN client is loaded only on entering online mode; local offline and `file://` play must remain functional.
- `supabase/migrations/20261024_online_single.sql` holds tables, constraints, RLS, private Realtime policies, and privileged RPCs; `supabase/functions/online-room/index.ts` holds guest authentication, validation, and room actions. Service-role credentials belong only in Edge Function environment variables. `online-config.js` contains the public project URL and publishable key; update the service-worker cache version when editing it. The remote GitHub `main` may lag this workspace; review remote changes before any sync, and do not push without explicit permission.

## Checks before completion

Run `node --check script.js`, `node --check online-rules.js`, `node --check online.js`, and `node --check service-worker.js`. Check color selection/persistence, local series/draws/orientation, AI, replay export/import, statistics isolation, offline local play, and desktop/mobile layouts. For online, compare the pure rules against the local test hook, then check room creation/join, private presence, moves and turn locking, maximum capture chains, promotion, stale/invalid move rejection, disconnect/reconnect, rematch, leave, and database resynchronization in two browsers against a live Supabase project. Mark live checks NOT RUN until a project URL and publishable key exist. Confirm only intended files changed; update the changelog with each feature or fix.

**Requirements note:** This agent guide is not intended as a full ISO/IEC/IEEE 29148 requirements specification. It applies clear, testable implementation constraints but simplifies formal requirement IDs, rationales, priorities, acceptance criteria, and traceability; the player-facing behavior is documented in README and the in-app How to Play screen.
